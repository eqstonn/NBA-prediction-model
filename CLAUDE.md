This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Bayesian NBA game predictor. Each team has independent **offensive** and **defensive** bell curves (mean + std) for Dean Oliver's Four Factors: eFG%, TOV%, ORB%, FTR. These are learned game-by-game with PyMC and stored in `priors.json`. Predictions are 10,000-draw Monte Carlo sims that turn the factors into points.

- **Strength of schedule:** a game's expected factor = `(team offense + opponent defense) / 2`. The observed value updates *both* curves, so a strong game against a good defense moves the rating more than the same game against a bad one.
- **Prior → posterior:** after each game, the posterior mean/std is written back and becomes that team's prior for its next game.

### Current state and goal

- `priors.json` was trained on all games **before the current (2026-27) season** started, using the Kaggle "NBA Dataset: Box Scores and Stats (1947 - Today)" CSV.
- **Next goal:** take games played this season, update the priors from each one (online learning, no retraining from scratch), and keep predicting upcoming games. The README's v2.0 "Automated Daily Updater" (fetch box scores with `nba_api`) is this feature.
- **Other v2.0 roadmap items:** time decay so recent games weigh more, and garbage-time filtering (15+ point margins in the 4th quarter). Dynamic pace (Phase 7) and the home-court boost (Phase 8) are live, together with the fitted simulation σ (the **pace-home switch**, see the comparisons in Gotchas). Rest days / back-to-backs (Phase 9) are live too since the **rest switch** (the live model is pace-home-rest).

## Architecture

All code is in `code/` as flat scripts that import each other by bare module name (`from data_prep import ...`). Run them as `python code/<file>.py`, not with `-m`.

**Training path:** `data_prep.py` → `dynamic_model.py` → a new priors file
- `data_prep.py` reads the Kaggle `TeamStatisticsExtended.csv`, which isn't in the repo. Training looks for it at `stats/TeamStatisticsExtended.csv` or `stats/NBA-DataSet/TeamStatisticsExtended.csv` (the unzipped dataset, currently there), or takes `--csv`. `clean_data_frame(df, before, years)` drops rows without `gameId`/`gameType`, keeps games before `before` and within `years` of it (`years=None`: all history), and sorts chronologically. Called without `before`, it keeps the original behavior: the last 3 years up to today. It then selects the camelCase Four Factor columns (`effectiveFieldGoalPercentage`, `teamTurnoverPercentage`, `offensiveReboundPercentage`, `freeThrowAttemptRate`). Factors are fractions (e.g. eFG ≈ 0.54), not percents.
- `dynamic_model.py --out FILE --before DATE [--years 3 | --all-history] [--engine exact|pymc]` starts every team in the window from `state_manager.default_priors` (flat league averages, std 0.05). Each row (one per team per game, so each game twice) goes through `bayes_update.update_game(priors, row, tau=0)`, and the result is written to `--out`. With no flags it trains the live model (fitted σ, team paces, home boost, rest). It refuses to write `priors_pre_2026-27.json`, `priors_pre_2026-27_pace-home.json`, `priors_pre_2026-27_pace-home-rest.json`, `priors.json`, `applied_games.json`, `priors_2026-27_base.json` or `model_params.json`. **Use `--before 2026-10-03`**, the first day of the 2026-27 preseason. The Kaggle file gives a `gameType` only to *this* season's preseason games (Oct 3–16, 2026; older preseasons have none and are dropped), so a later cutoff would train on 2026-27 preseason games and add a 38th team ("Lions", `50015`). With 2026-10-03 and the default 3 years, training gets exactly the original's 3,963 games (2023-10-24 to 2026-06-13: regular season, playoffs, play-in, the 2025 Cup final, and 2026 All-Star games, which only touch the 7 non-NBA All-Star team keys) and its 37 teams. The old in-place mode (update `priors.json`, window relative to today) is gone, because it double-counted this season.
- **`priors_pre_2026-27_exact.json`** is that 3-year exact retrain. It differs from the PyMC-trained frozen file by a median 0.0026 (max 0.025) on NBA means, and the frozen stds are ~8% smaller. Same window, same game types, no restart double-counting (all three were checked by sweeping the alternatives). The cause is MCMC error compounding over ~250 chained fits per curve with tau = 0.
- `bayes_update.py` holds the shared per-row update. `update_game(priors, game, tau, random_seed, engine, sigma)` takes `game = {"team", "opponent", "eFG", "TOV", "ORB", "FTR"}`, the team's offensive line. Per factor `f` the model is offense `N(m_o, s_o²)`, defense `N(m_d, s_d²)`, observed `N((o+d)/2, σ_f²)`. It writes back each curve's posterior mean/std. With `tau > 0`, the curves in this fit are first widened to `sqrt(std² + tau²)`.
  - **Noise σ_f** (`params.py`, Phase 6) is set **separately for the update and the simulation**.
    - `"fitted"` = `model_params.json["sigma"]` (eFG 0.0637, TOV 0.0364, ORB 0.0719, FTR 0.0854).
    - `"legacy"` = the pre-Phase-6 values, fixed in code: the update used 0.05 for every factor, the simulation 0.05/0.02/0.05/0.02 (`params.LEGACY_UPDATE_SIGMA` / `LEGACY_SIM_SIGMA`).
    - **Defaults everywhere: fitted for the update and the simulation** (`params.update_sigma()`, `params.sim_sigma()`; training, `--update`, `--replay`, `simulation.py`, `predict.py`, `build_site.py`, the prediction log). Phase 6 used legacy for the simulation, which only scored best with the old points formula (pace off); see the comparisons below.
    - Override with `--sigma-update` / `--sigma-sim`, or by passing `sigma=` dicts.
  - **`fit_sigma.py`** estimated σ from the training data only (Kaggle, 3 years before 2026-10-03; no 2026-27 game). Method: the one-step-ahead (prequential) predictive likelihood. For each candidate σ it runs the exact training pass and scores each row's actual value under the forecast `N((m_o+m_d)/2, (s_o²+s_d²)/4 + σ²)` made before that row. It then picks the best σ per factor on a grid (0.005 steps, then 0.0001). At the optimum the squared standardized residuals average 0.99–1.00. Training has tau = 0, so σ also absorbs some team change across the 3 seasons. `model_params.json["sigma_fit"]` records the data, method and log-likelihoods.
  - **`engine="exact"` (default everywhere):** the closed-form conjugate (Kalman) update in `_fit_exact`. With `V = (s_o² + s_d²)/4 + σ_f²` and `surprise = y − (m_o + m_d)/2`: `m_o' = m_o + (s_o²/2)/V · surprise`, `s_o' = sqrt(s_o² − (s_o²/2)²/V)`, and the same for defense. Instant, exact, no seeds needed.
  - **`engine="pymc"`:** the original PyMC model in `_fit_pymc` (NUTS, `pm.sample(1000)`). Same answer plus sampling noise: over the 2026-27 replay, median 0.0012 and max 0.0050 from exact, with no bias. Kept for model extensions that aren't Normal/linear (bounded priors, Student-t, learned σ, hierarchical).
  - pymc is imported lazily (`_pymc()`), only on the first PyMC fit; `PYTENSOR_FLAGS="cxx="` is set at the top of the module before that. **Import pymc only through this module.**
- `--engine exact|pymc` is accepted by `dynamic_model.py` and `update.py` (`--update`, `--replay`, `--trial`). `--sigma-update` is accepted by both. `--sigma-sim` is accepted by `update.py` (`--update`, `--replay`) and `build_site.py`. `--sim-corr` likewise by `update.py` and `build_site.py`; `--pace` by those two and `dynamic_model.py`. Every `applied_games.json` entry records `engine`, `sigma_update`, `sigma_sim`, `sim_corr`, `pace`, `home`, `rest` and `neutral` (the 210 games before the switches were rewritten with the live settings when each went live).
- **`fit_sim.py`** (Phase 7) fits three more `model_params.json` sections from the training data only. It keeps `sigma`/`sigma_fit` as they are, and `fit_sigma.py` keeps these three likewise. Fits are scored on NBA-vs-NBA games.
  - `factor_corr`: the 8×8 correlation of the game noise, ordered `params.CORR_LABELS` (team eFG/TOV/ORB/FTR, then opponent). It is the correlation of the standardized one-step-ahead residuals of the exact training pass (the same residuals `fit_sigma.py` scores). Each game is one 8-vector, used in both team orders, after a one-season burn-in. Every value is small: the largest are TOV–ORB within a team (+0.20) and FTR–opponent FTR (+0.14); eFG–opponent eFG is only +0.03.
  - `points`: constants of the corrected points formula, `ft_pct` 0.7819, `possession_offset` 2.071 and `rebound_chances` 0.9204 (see the prediction path).
  - `pace`: the game noise `sigma` (4.84 possessions, the predictive-likelihood maximum) and training's flat start (`start_mean` 99.91, `start_std` 5).
- **Pace** (`--pace on`), stored as `priors[team]["pace"] = {"mean", "std"}` in possessions per game.
  - **Model:** game possessions ~ N((pace_a + pace_b)/2, σ_pace²), updated exactly by `bayes_update.update_pace`. It uses `conjugate_pair`, the same formula as offense/defense.
  - **Training:** `dynamic_model.py --pace on` adds it, using each game's average of the two teams' Kaggle `possessions`; the factor curves come out identical to `--pace off`. `priors_pre_2026-27_pace.json` is the sigma-update training plus paces.
  - **In season:** the reset sets pace stds to 2σ_pace/√N and drift is tau = 2σ_pace/M per game. This is the ratings' 0.1 = 2 × 0.05 rule in pace units.
  - **Data:** in season, possessions come from NBA.com's `boxscoreadvancedv3`, cached in `stats/boxscores_advanced/<gameId>.json` (all 210 games are cached). A game without them is skipped and not recorded.
- **Home court** (`--home on`, Phase 8; `model_params.json["home"]`, fitted by **`fit_home.py`** from training data only). The home team's offensive line gets `home["offense"][f]` added to its expected value, `(o + d)/2 + boost`, and the away team's line gets `home["defense"][f]`. This happens in the update (`update_game(..., offset=)`, which fits `y − offset`) and in the simulation (team_a = home).
  - **Only the gap is identifiable.** Per factor the data pin down only the gap δ_f = offense − defense. A shift common to both lines is the same thing as a different league level of the ratings, and only neutral games could separate them (15 in training). Profiled after the first season, it changes the log-likelihood by < 1.5 over ±0.01. So the gap is split evenly, offense +δ/2 and defense −δ/2, and the ratings are neutral-site strength.
  - **Fit:** per-factor δ by the one-step-ahead likelihood of the exact training pass with the boost (as `fit_sigma.py`). Results, as gap (SE): eFG +0.0086 (0.0014), TOV −0.0016 (0.0008), ORB +0.0023 (0.0016), FTR +0.0052 (0.0019). That is about +2 pts of home margin.
  - **No pace boost:** an additive possessions boost (±1) and a home-tempo weight both change the log-likelihood by ≈ 0.
  - **Neutral sites get no boost.** `boxscores.neutral_flags` uses NBA.com's `ScheduleLeagueV2`: `isNeutral`, or an arena in a different state/country than the home team's usual one. The 2023-24 schedule never sets `isNeutral`; the state rule catches its Mexico City, Paris and Las Vegas games and agrees with `isNeutral` in later seasons. The Spurs' Austin games stay home games, as on NBA.com.
  - **Neutral-flag data:** schedules are cached in `stats/schedules/<season>.json`; `--update` refreshes the current one, and training / `--replay --home on` read the cache and download only what's missing. `--home off` never reads them.
  - **2026-27 neutral games:** `0022600189` DEN @ IND (Mexico City, the only one among the 210 applied), `0062600001` the NBA Cup final (Hinkle Fieldhouse, Indianapolis), `0022600075` Paris and `0022600076` Manchester.
  - **Recorded data:** game dicts carry `"neutral"`, and new `applied_games.json` entries record `neutral` and `home`. `schedule.py` sets `neutral` for the website (NBA.com `isNeutral` / ESPN `neutralSite`).
  - **Files:** `priors_pre_2026-27_home.json` = the sigma-update training with the boost; `priors_2026-27_home.json` / `log_home.csv` = its replay (legacy sim σ, pace off).
  - **Live files (pace-home):** `priors_pre_2026-27_pace-home.json` = training with the live defaults (= the home training's factor curves + the pace training's paces; `--start-season`'s source, read-only); `priors_2026-27_pace-home.json` / `log_pace-home.csv` = its replay with N=20, M=30.
- **Rest** (`--rest on`, Phase 9, default on since the rest switch; `model_params.json["rest"]`, fitted by **`fit_rest.py`** from training data only).
  - **Rest days** (`rest.py`) come from NBA.com's season schedules (the same `stats/schedules/` cache as the neutral flags; `rest.rest_games(ids)` reads it and downloads only what's missing). Per team and game: `days` off since its previous game in the same season, category `"b2b"` (0), `"1"`, `"2+"`, and on back-to-backs `traveled` (last night's `arenaName` differs). Counted games: types 002/004/005/006 with known teams, not postponed; preseason (001) and All-Star (003) don't count. **Openers are `"2+"`**, and the previous season never counts, however close.
  - **Data check:** NBA.com and Kaggle agree on every training game's date. NBA.com also has 6 games the Kaggle CSV lacks altogether (2023 and 2024 Cup finals, 4 regular-season games); they count for rest, so 10 training rows get `"1"` where Kaggle's dates alone say `"2+"`.
  - **Counts:** training team-games: b2b 1,309 (876 traveled, 433 same arena: mostly home-home), 1 day 4,899, 2+ 1,704; 1,112 of 3,963 games have a team on a b2b. **2026-27 (210 games): 61 games with a team on a b2b, 13 with both, so 48 where rest differs.**
  - **Model:** a line's expected value gets `rest["offense"][rest of the offense team] + rest["defense"][rest of the defense team]` ("2+" = 0), added to the home boost (`params.rest_offsets`, `combine_offsets`). Game dicts carry `"rest": {"home": cat, "away": cat}` (`update.add_rest`); `simulate_factors(..., rest, rest_a, rest_b)`, `predict_game(..., rest, rest_home, rest_away)`; the website uses `rest.rest_lookup` (by team and date, since ESPN ids aren't NBA ids). With rest on, the simulation needs both teams' rest (ValueError otherwise) and `apply_game` needs `game["rest"]` (KeyError). `--update` takes rest from the schedule **plus every finished game** (`rest.rest_games(..., extra_games=)`), so a game the schedule leaves out (the game log ∪ schedule gotcha) still gets its rest and counts for its teams' next games; replays and training read the schedule only. `applied_games.json` entries record `rest`.
  - **Fit method:** the same one-step-ahead likelihood as `fit_home.py`, but solved exactly: in the exact (Kalman) update the variances don't depend on the observations and the means are linear in `y − offset`, so the forecast residuals are exactly linear in the rest parameters (checked to 1e-15). One training pass per parameter gives the linear map; the maximum is weighted least squares with exact SEs.
  - **Form chosen: the rest difference, back-to-backs only** (`defense = −offense`, one parameter per factor; two equally rested teams get nothing). Best AIC of 7 forms (+17.0). Both-teams vs difference: LR χ² 1.3 on 4 df, p = 0.87 (8.9 on 8, p = 0.35 with 1 day); a 1-day effect: p = 0.70; splitting b2b by travel: p = 0.29 (same-arena b2bs even look worse). On a held-out third season every difference form gains (+1.1 to +2.4), the chosen one +2.0.
  - **Effect** on a line whose offense is on a b2b (opposite sign when its defense is), SE: eFG −0.0063 (0.0015), TOV +0.0013 (0.0009), ORB −0.0037 (0.0017), FTR −0.0008 (0.0020). **A b2b team vs a rested one: −2.57 pts of margin (SE 0.52)**, at league-average teams and pace; eFG alone is −1.84.
  - **No pace effect:** b2b −0.14 (0.16) possessions per team. Refitting the home gap jointly with rest moves it by ≤ 0.0001, so rest and home aren't confounded.
  - **Live files (pace-home-rest):** `priors_pre_2026-27_pace-home-rest.json` (training with the live defaults; factor curves differ from pace-home, paces identical; `--start-season`'s source, read-only), `priors_2026-27_pace-home-rest.json` / `log_pace-home-rest.csv` (replay, N=20, M=30).
- **`train_calibration.py`** checks every simulation setting on the training data, with no 2026-27 game. Its variants spell out every switch: `live` = fitted sim σ + pace (the live simulation), `old-live` = legacy sim σ, pace off (Phase 6); `--home` defaults to on. It runs the exact training pass (plus paces, plus the boost with `--home on`) and simulates each NBA game after the first season one step ahead, with the home team as team_a. It prints Brier, accuracy, confidence, totals, home margin, simulated vs real margin SD and slope, plus paired Brier differences with SEs.
- **The live model is the pace-home-rest pipeline**: `priors.json` = `priors_2026-27_pace-home-rest.json` (exact training + exact replay from `priors_pre_2026-27_pace-home-rest.json`, N=20, M=30; fitted σ in the update and the simulation, team paces, home boost, rest, sim_corr off). All 210 games in `applied_games.json` are recorded as `engine: "exact"`, `sigma_update: "fitted"`, `sigma_sim: "fitted"`, `sim_corr: "off"`, `pace: "on"`, `home: "on"`, `rest: "on"` plus their `neutral` flag (only `0022600189`), keyed in (date, gameId) order, the same order as `log_pace-home-rest.csv`. Before that, the pace-home pipeline was live (`priors_2026-27_pace-home.json`, commit `1200818`), then the Phase 6 sigma-update pipeline (`priors_2026-27_sigma-update.json`), and before that `priors_2026-27_exact.json` (commit `ba4fdd3`). Use the defaults for everything.
- `state_manager.default_priors(team_ids)` returns the flat starting curves; `initialize_priors` writes them to `priors.json` (destructive).

**In-season path:** `priors_pre_2026-27.json` (frozen) → `update.py` → `priors.json` + `applied_games.json`
- `update.start_season(n, from_path, pace)` reads only the preseason file: `update.START_PRIORS_PATH` = `priors_pre_2026-27_pace-home-rest.json` by default, or `--from` (e.g. the frozen snapshot, which has no paces and so needs `--pace off`; with pace on a source without paces is refused before anything is written). For the 30 NBA teams (`schedule.NBA_TEAMS`) it keeps every mean and sets every std to `0.1/sqrt(n)` (pace std `2σ_pace/sqrt(n)`), so last season counts as `n` games of evidence. The 7 non-NBA teams are copied unchanged. It writes `priors.json` and resets `applied_games.json` to `{}`, which maps `game_id` → info for games already applied.
- `update.write_json` writes atomically and raises `PermissionError` if pointed at a read-only preseason file (`update.READ_ONLY_PATHS`: the frozen snapshot, `priors_pre_2026-27_pace-home.json` and `priors_pre_2026-27_pace-home-rest.json`). Route all writes through it.
- `boxscores.py` is the 2026-27 data source (NBA.com via nba_api, not Kaggle). Its only network functions are `_download_game_log`, `_download_schedule` (also cached per season in `stats/schedules/` for the neutral-site flags), `_download_box_score` and `_download_advanced_box_score` (possessions, only with `--pace on`); tests replace all four (`tests/fake_nba.py`).
  - **Endpoints:** every request goes through nba_api to `https://stats.nba.com/stats/<endpoint>`: `leaguegamelog`, `scheduleleaguev2`, `boxscorefourfactorsv3` and `boxscoreadvancedv3`.
  - **Game list = game log ∪ schedule.** The game log is unreliable: on 2026-11-17/18 it listed 205, 204, 209 games and kept leaving out the final DEN @ IND game (`0022600189`, Nov 7, Mexico City). So `fetch_finished_games` also takes the `ScheduleLeagueV2` games with `gameStatus == 3`. `combine_game_lists` merges the two by gameId (the game log's details win) and prints a `WARNING:` for each game missing from either list or differing in date, teams or score. `run_update` returns these as `"disagreements"`.
  - **Which games:** from the game log, only the season types `"Regular Season"` and `"IST"` (NBA Cup) are requested, nothing else. Schedule games get their season type from the gameId and the NBA Cup label/subtype. `select_games` keeps game IDs starting `002` (regular season, which includes Cup group games, quarterfinals and semifinals) or `006` (Cup final, listed only under IST), played on or after `OPENING_NIGHT = 2026-10-20`, sorted by (date, gameId). Preseason is `001`/`"Pre Season"`, play-in `005`, playoffs `004`.
  - **Four factors:** from NBA.com's `BoxScoreFourFactorsV3`, the source of the Kaggle columns. **Don't recompute factors from basic box scores**: NBA.com's ORB%/TOV% include team rebounds and its own possession count, so simple formulas are off by up to ~0.05. `get_game_factors` returns `(factors, None)` or `(None, reason)`. Complete box scores are cached in `stats/boxscores/<gameId>.json` (gitignored); incomplete ones are never cached.
  - Every request is throttled (0.6 s) and retried 4 times with backoff of 2, 4 and 8 s.
- `update.apply_game(priors, game, m)` makes two `update_game` calls per game (home offense vs away defense, then away vs home) with `tau = 0.1/m` (M=30). So each of the two teams' 8 curves widens once per game. Stds then settle near ~0.019 instead of collapsing.
- `update.run_update(through, limit, m)` (`--update`) loads `applied_games.json`, skips games already in it, and applies the rest oldest first.
  - **Skipped games:** a game whose box score can't be downloaded or is incomplete is skipped and **not recorded**, so the next run retries it. It is then applied after later-dated games, slightly out of order.
  - **Crash-safe saving:** each game is saved with three atomic writes: `applied_games.json` gets the entry with `"pending": <fingerprint of new priors>`, then `priors.json`, then the pending mark is removed. `load_applied()` resolves a leftover pending entry by fingerprint (kept if `priors.json` has the game, dropped otherwise). A fit error aborts the run with nothing half-saved.
  - **`applied_games.json` entries:** `{gameId: {"date", "matchup", "score", "nba_cup"}}`. Its key order is the order games were actually applied.
  - **Seeded fits (pymc engine):** PyMC fits use `random_seed = update.fit_seed(gameId)` (the gameId as an int), so runs are reproducible. The first 210 games (through 2026-11-17) were applied before this, without seeds.
- **Prediction log** (`predlog.py`): before a game is applied, `log_prediction` predicts it from the current priors with `predict.predict_game(..., seed=predlog.PREDICT_SEED)` and appends a row to `prediction_log.csv` (`--log` overrides). Columns: `date, game_id, home, away, predicted_winner, win_pct, proj_home, proj_away, actual_home, actual_away`; `win_pct` is the predicted winner's probability in percent. `append_rows` skips game_ids already in the file, so reruns never duplicate rows. Each run ends by printing the log's winner accuracy, spread MAE and Brier score (`predlog.metrics`). The log only covers games applied after this feature was added; `log_base.csv` from a replay covers the whole season.
- **Replay** (`update.replay`, `--replay --from --out --log`): reset from `--from` (N via `--n`), then every game in `applied_games.json` sorted by (date, gameId), each predicted + logged before it is applied, from the box-score cache (no network if cached). It writes only `--out` (at the end) and `--log` (rebuilt from scratch), and refuses outputs that are `priors.json`, `applied_games.json`, `prediction_log.csv` or the `--from` file. Use it to test model changes on the same season, then `compare.py` the logs.
- **`compare.py`** scores 2+ logs on the games present in every log and marks the best value per row with `*`.
- Cost: with the exact engine, fitting is instant (the whole 210-game replay takes ~1 s), so the time goes to the simulation for the prediction log and ~0.9 s per box-score download. With `--engine pymc`, it's about 3–5 s per game on AC power (2 fits, mostly PyTensor recompiling the model each time); the 210-game PyMC replay took 69 min on battery. **On battery the laptop throttles badly**, so run PyMC jobs plugged in.

**Betting lines (Phase 10a; data only, the model never reads them):**
- `lines.py` saves Vegas lines from The Odds API (`GET /v4/sports/basketball_nba/odds`, `regions=us`, `markets=h2h,spreads,totals`: **one request = 3 credits**, free plan 500/month). The key comes **only** from the `ODDS_API_KEY` environment variable; it must never be written to a file, printed or put in an error message (`lines.redact`; `_download_odds` raises `from None` because the request URL holds the key). `.env` is gitignored. `_download_odds` is the only network function; no retries.
- **`data/lines_2026-27.csv` is append-only** (committed): one row per upcoming game per run, `fetched_at` (UTC) + NBA.com `game_id`, `spread_home` (negative = home favored), `total`, `ml_home`/`ml_away`, vig-free `home_win_prob`, `n_books_*`. Consensus = median across the US books; moneylines are medians of decimal odds converted back to American. `append_rows` refuses a file with other columns and never rewrites rows. Unmatched games go to `data/lines_unmatched_2026-27.csv` and are printed as warnings; raw responses to `stats/odds/` (gitignored). Started games are not saved (live odds).
- **Matching:** US Eastern date of `commence_time` + home/away team names (`NAME_TO_ID`; The Odds API says "Los Angeles Clippers") against NBA.com's cached schedule (refreshed once if a game doesn't match); then the same with home/away swapped (`flipped`, neutral sites), the numbers always from NBA.com's home side.
- **Closing line** (`closing_line(s)`) = a game's last snapshot with `fetched_at` < tip-off (the `tipoff_utc` of its newest snapshot). A morning `--update` only gives the morning line; run `python code/lines.py` near tip-off for real closing lines.
- `update.py --update` takes one snapshot after listing games (`--lines on|off`, default on, only with `--update`). No key or a failed request prints a `WARNING` and the update goes on; `run_update` returns it as `"lines"`. Tests: conftest's autouse fixture removes the key, makes `_download_odds` raise and points the lines files at a temp folder.
- **`historical_lines.py`**: the training seasons' lines from Kaggle "NBA Betting Data | October 2007 to June 2026" (`cviaxmiwnptr`, `nba_2008-2026.csv`, needs a Kaggle login, put at `stats/betting/`). Spread + total for every game; **moneylines are empty from mid 2022-23 on**. Matched by (date, home, away) to the training games (NBA vs NBA, 3,956): **100% matched** (checked 2026-11-19). 5 score disagreements are data errors, not other games (NBA.com checked); the 6 extra betting rows are the 2023/2024 Cup finals and the 4 games the Kaggle training CSV lacks.

**Prediction path:** `priors.json` → `simulation.py` → `predict.py` → `build_site.py` (+ `schedule.py`)
- `simulation.simulate_factors(team_a, team_b, priors, seed=None, sigma=None, sim_corr="off", pace="on", home="on", neutral=False, rest="on", rest_a=None, rest_b=None)` does the following (`seed=None` = fresh randomness, as the website uses; an int = reproducible, as the prediction log uses; `sigma=None` = `params.sim_sigma()`, fitted by default). With the defaults it needs team paces in the priors and both teams' rest (`"b2b"`, `"1"`, `"2+"`); the quick CLI sim (`python code/simulation.py`) has no dates and passes `"2+"` for both, which adds nothing.
  - draws each side's offense and defense factors, blends them `(o + d)/2`
  - adds game noise σ_f per factor (fitted: 0.0637/0.0364/0.0719/0.0854; legacy: 0.05/0.02/0.05/0.02). `sim_corr="off"`: drawn independently for each factor and team (`independent_factors`, the original draw order). `"on"`: the 8 noises are drawn jointly with `factor_corr` (`correlated_factors`, Cholesky).
  - converts to points. `pace="off"`: `legacy_points`, the original `possessions = 100·(1−TOV)·(1+ORB·(1−eFG))`, `points = possessions·(2·eFG + 0.77·FTR)`. Its "possessions" are really FGA, and it ignores free-throw possessions: +9.7% FGA, **+21.6 pts per game even with the actual possessions; the fixed 100 adds only +0.2**. `pace="on"`: possessions ~ N((pace_a + pace_b)/2, σ_pace²) from the teams' pace curves, then `points()`: `FGA = (poss + 2.071)(1−TOV)/(1 + 0.44·FTR − 0.9204·ORB·(1−eFG))`, `points = FGA·(2·eFG + 0.7819·FTR)`. That is NBA.com's own definitions solved for FGA. On actual factors + possessions it is off by −0.13 per game on training data and −0.8 on 2026-27, MAE ~3.1.
  - also returns `margin_sd` (SD of the simulated margins) and `possessions`; `predict_game` doesn't pass them on.
  - Both switches off = the old simulation draw for draw.
  - `home="on"` (with `neutral=False`): team_a (the home team) gets the home boost's offense shifts on its line and team_b the defense shifts. `"off"` adds nothing, so the draws are unchanged.
- `predict.py` is the **only** interface between the website and the model. `predict_game(home_id, away_id, model, rest_home=, rest_away=)` (live defaults; `neutral=True` for a neutral site) returns `{home_win_pct, away_win_pct, home_score, away_score}`, or `None` if a team isn't in the priors. If the model's internals change, keep this return shape and only edit this file. Home team = `team_a`.
- `schedule.fetch_games(start, days)` tries NBA.com's public schedule JSON and falls back to ESPN's scoreboard. Both are normalized to one game dict shape (documented at the top of `schedule.py`). ESPN abbreviations are mapped back to NBA team IDs. NBA.com currently returns 403 to our request, so in practice ESPN is used.
- `build_site.py` writes a static `site/index.html` (self-contained HTML/CSS/JS) and `site/predictions.json`. Finished games are graded against the model's pick.

### `priors.json` shape

Keys are **NBA.com team IDs as strings** (e.g. `"1610612738"` = BOS):
```
{ "<teamId>": { "offense": {"eFG": {"mean", "std"}, "TOV": ..., "ORB": ..., "FTR": ...},
                "defense": { ...same four... } } }
```
It has 37 keys: the 30 NBA teams plus a few non-NBA teams from the Kaggle data. "Defense" factors are what the team *allows*.

## Gotchas

- **`priors_pre_2026-27.json` is a frozen, read-only snapshot** of `priors.json` from before any 2026-27 games were applied (git tag `pretrained-2025-26`). No code may ever write to it. Read it to reset or compare. The live pipeline restarts from `priors_pre_2026-27_pace-home-rest.json` instead (`--start-season`, also read-only); a restart from the frozen snapshot is `--start-season --from priors_pre_2026-27.json --pace off`.
- **Updates are not idempotent.** Feeding the same game twice moves the priors twice. Any in-season updater must record which games it has already applied. Note that ESPN `game_id`s are ESPN event IDs, not NBA `gameId`s.
- **Never train on 2026-27 games, including the preseason.** Always pass `--before 2026-10-03` to `dynamic_model.py`; the in-season updater applies this season's games.
- **Model comparisons so far** (210 games, through 2026-11-17, `compare.py`): `log_base.csv` (PyMC training + PyMC season) gets 69.0% of winners, spread MAE 12.08, Brier 0.2085. `log_exact.csv` (exact training + exact season) gets 71.0%, 12.02, 0.2065. The gain comes from the clean retraining, not the season engine (same start, engine only: Brier −0.0005). It is 1.5 standard errors, so not yet significant.
  - **Phase 6:** `log_sigma.csv` (fitted σ in update and simulation) gets 69.5%, spread MAE 11.98, Brier 0.2100, avg confidence 62.1%. **`log_sigma-update.csv`** (fitted update σ, legacy simulation σ: the Phase 6 defaults and live model) gets 69.5%, **11.98, 0.2057**, avg confidence 66.9%. That is the best Brier and spread so far, but only −0.4 SE vs `log_exact`, so not significant. Fitted σ in the simulation only gives 0.2104.
  - **Why fitted σ hurts in the simulation:** the simulation draws the four factors independently, so with the true per-factor σ its margin SD is 19.9 pts against 15.5 in real games. Win % becomes too timid: average confidence 62% vs 71% accuracy. Real factor errors are correlated (e.g. more missed shots, more offensive rebound chances). `compare.py` shows avg confidence next to winner accuracy for this calibration check.
  - **Phase 7** (`compare.py` now also shows projected vs actual total and the margin error SD):
    - **The replays:**
      - `log_corr.csv` (`--sim-corr on`, fitted sim σ): 69.5%, Brier 0.2084, confidence 63.5%, total 248.2.
      - `log_pace.csv` (`--pace on`, legacy sim σ): 70.0%, 0.2084, 65.7%, **total 227.0 vs 227.4 actual**.
      - `log_corr-pace.csv` (both on, fitted sim σ): 69.5%, 0.2101, 63.4%, total 226.8; its simulated margin SD is 14.9 vs the real 15.4.
      - None beats `log_sigma-update` (0.2057). The combined one is +0.0045, 1.3 paired SE, not significant.
    - **Why the old simulation looked calibrated:** two errors cancelled. The old formula stretches projected margins (real margins are only 0.85× the projection), and its legacy σ makes the simulated spread too narrow (13.6 vs 15.5 real). With the corrected formula the scale is right (1.05).
    - **Why the correct spread looks timid this season:** the 210 games' accuracy (69.5–70%) is ~2 SE above what their own 15.4-point error spread predicts (62.7%).
    - **On training data the order reverses** (`train_calibration.py`: 2,636 NBA training games, seasons 2–3 of the window, no 2026-27 game). There the then-live simulation is 6.0 pts overconfident (Brier 0.2346). Combined (corr-pace): 0.2290, overconfident by 1.6 pts, **−0.0056 = 5.0 paired SE better**. Pace + fitted σ without the correlation does as well; the correlation alone adds little.
    - The correlation was not made live; pace is live since the pace-home switch (below). `priors_2026-27_corr.json` equals `priors_2026-27_sigma-update.json`, and `priors_2026-27_corr-pace.json` equals `priors_2026-27_pace.json`: the simulation settings never change the update.
  - **Phase 8, home court:**
    - **This season:** `log_home.csv` (`--home on`, otherwise the Phase 6 settings) gets 67.6%, Brier 0.2064, confidence 67.3%, spread MAE 12.12, projected home margin +2.04 vs +1.36 actual (the Phase 6 model's is −0.10). Versus `log_sigma-update`: +0.0008 Brier = **+0.2 paired SE**, i.e. no measurable difference. The 22 picks it flips all go to the home team, which won 9 of them.
    - **Training check:** home on helps every simulation variant. For the Phase 6 simulation, Brier 0.2316 vs 0.2346, **−0.0030 = 2.8 paired SE**, and accuracy 62.7% vs 60.9%. Projected home margin is +1.70 with the corrected formula (+2.15 with the old one) vs +1.80 actual. The best variant is pace + fitted σ + home: 0.2264 (−0.0082, 5.5 SE), confidence − accuracy −0.3 pts.
    - Made live together with pace + fitted sim σ (the pace-home switch, below).
  - **Pace-home switch (live):** pace + fitted sim σ + home, sim_corr off, N=20, M=30.
    - **This season:** `log_pace-home.csv` gets 65.7%, spread MAE 12.04, Brier 0.2117, confidence 62.5%, total 226.9 vs 227.4 actual, home margin +1.54 vs +1.36. Versus `log_sigma-update`: **+0.0060 Brier = +1.3 paired SE** (20 picks differ, the new pick is right in 6); versus `log_home`: +0.0053 (+1.3 SE). Worse on these 210 games, but not significantly, and these games' accuracy is ~2 SE above what their own error spread predicts (Phase 7 note).
    - **Training check** (`train_calibration.py --variants old-live live --home off on`, 2,636 games): old live (old-live, home off) Brier 0.2346, overconfident by 6.0 pts; **live (home on) 0.2264, confidence − accuracy −0.3 pts, −0.0082 = 5.5 paired SE better**. Live without home: 0.2289 (−4.5 SE); old-live with home: 0.2316 (−2.8 SE). The switch was made on this evidence.
  - **Phase 9, rest** (live settings + `--rest on`):
    - **This season:** `log_pace-home-rest.csv` gets 67.6% (vs 65.7%), spread MAE 11.96 (12.04), Brier 0.2110 (0.2117), confidence 62.5% (62.5%), total 226.9 vs 227.4 (unchanged), home margin +1.50 vs +1.36 actual (+1.54). Versus `log_pace-home`: **−0.0007 Brier = −0.4 paired SE**; 10 picks differ, the rest pick is right in 7. On the 48 games where exactly one team was on a b2b, that team's margin was −2.38 actual, +0.76 projected by the live model, −1.81 with rest (Brier −0.0015, SE 0.0079).
    - **Training check** (`train_calibration.py --variants live --rest off on`, home on): 0.2264 → **0.2255, −0.0009 = −1.6 paired SE**, confidence − accuracy +0.1 pts. The rest effect was fitted on these same games (4 parameters), so this is slightly optimistic.
    - **Made live** (the rest switch): the same steps as the pace-home switch, `--rest on` as the default, `priors.json` <- `priors_2026-27_pace-home-rest.json`, `rest: "on"` recorded for all 210 games.
- **Trained stds collapsed** to ~0.005 because training never re-inflates them (tau=0). The season reset (`0.1/sqrt(N)`) plus per-game tau is what fixes this for 2026-27.
- **Per-game mean shift = gain × (observed − expected)**, with gain = `(s_o²/2)/V`. At season-start stds the gain is 0.093 with σ = 0.05. With the fitted σ it is about 0.16 for TOV, 0.06 for eFG, 0.05 for ORB and 0.034 for FTR. A fixed cap like "< 0.01" fails on real games, so `test_per_game_mean_shifts_damped` checks `shift ≤ max_gain(σ_f) × |surprise|` for both σ modes.
- **Smart App Control is on** on this machine. The first import of scipy/pandas DLLs after an install can be blocked ("An Application Control policy has blocked this file") or take ~35 s while Windows checks them. Re-running usually works.
- NBA.com's CDN schedule JSON returns 403, but `stats.nba.com` through `nba_api` works.
- `state_manager.initialize_priors` uses a CWD-relative `priors.json`; `dynamic_model.py`, `update.py` and `predict.py` resolve paths from `REPO_ROOT`.
- **Windows compatibility:** don't use `strftime` codes like `%-d` or `%-I` (Linux/macOS only). Always pass `encoding="utf-8"` when reading or writing files, because the default here is cp1252.
- `build_site.py` uses `zoneinfo` for US Eastern time. On Windows this needs the `tzdata` package, which is listed in `requirements.txt`.
